## 核心定位与设计底线（必须100%严格遵守，不得有任何偏离）
本系统是**中心化持牌运营、联盟链深度赋能**的合规交易所，核心交易机制为「**链下高性能中心化撮合 + 订单全生命周期链上存证确权 + 全链路监管穿透**」。
- 必须完整保留中心化交易所的核心优势：低延迟、高并发的中心化撮合引擎，主要交易对象是各个景区商业用户在链上发布的景区门票nft，采用ERC3525，交易所支持多种拍卖模式 以及对长期期限的门票的订单簿交易模式，不得改造为去中心化交易所（DEX）、不得采用AMM模式、不得将撮合逻辑上链执行；

- 所有设计必须以国内金融持牌经营合规为前提，核心目标是满足监管机构穿透式监管、实时审计、合规核查的刚性要求，同时保障投资者的交易知情权与资产安全。

# 一、强制约束与不可突破的设计红线
1.  **撮合与上链的权责边界红线**：所有订单的撮合匹配、价格发现逻辑100%在链下中心化撮合引擎完成，确保交易性能；区块链仅承担订单全生命周期的存证、确权、验签、对账、监管功能，绝对禁止将撮合计算、订单簿上链，不得影响交易所原有交易性能与用户体验。
2.  **上链数据刚性规则**：严格遵循「**核心数据必上链、非必要数据不上链、隐私数据不上明文**」原则，仅将与订单、资金、合规、监管相关的、需防篡改、需交叉核验、需责任追溯的核心数据上链；用户完整隐私信息、原始行情快照、高频中间计算数据、非监管类运营数据严禁上链，仅可上链其脱敏后的SM3哈希摘要。
3.  **不可篡改确权红线**：所有上链的订单、交易、资金数据必须携带对应主体的国密SM2数字签名与可信时间戳，确保数据来源可溯、责任可定、内容不可篡改；用户订单必须携带用户本人的数字签名方可上链存证，交易所无权单方篡改、伪造用户订单数据。
4.  **多角色权责匹配规则**：交易所全业务链路的参与角色，必须与联盟链节点类型、链上权限、上链责任一一对应，权责清晰，无越权操作、无责任盲区。
5.  **监管优先规则**：监管机构拥有链上全量数据的只读审计权限，无需交易所授权即可实现穿透式查询、一键核验、异常告警订阅，监管指令与处置记录必须全流程上链留痕。

# 三、强制上链数据清单（订单全生命周期为核心，100%覆盖不得遗漏）
以下为监管必需、与交易核心链路深度绑定的上链数据，需明确每个数据项的**上链主体、触发时机、上链方式、核心目的、验签规则**，非清单内数据严禁上链：

## （一）订单全生命周期核心数据（深度融合撮合业务的核心上链项）
### 1. 订单创建与下达阶段（下单即上链，与撮合引擎接单并行执行）
- 具体数据项：用户签名的订单唯一标识ID、订单原始参数哈希（交易对、价格、数量、买卖方向、订单类型、杠杆倍数）、用户公钥哈希、下单可信时间戳、用户SM2数字签名、交易所接单确认签名
- 上链主体：用户（签名确权）+ 交易所运营方
- 触发时机：用户下单指令发出、交易所撮合引擎接单的同时，并行触发上链
- 上链要求：单笔订单实时上链，高频小额订单可采用毫秒级批量打包上链；必须通过用户签名验签，确保订单未被篡改；核心目的：锁定订单原始状态，防止交易所篡改用户订单、伪造订单，为后续撮合成交提供可信锚点

### 2. 订单撮合与匹配阶段（撮合即锚定，匹配结果实时上链）
- 具体数据项：对应买卖双方订单ID哈希、撮合匹配记录哈希、撮合价格、撮合数量、撮合引擎编号、撮合可信时间戳、交易所撮合引擎SM2数字签名
- 上链主体：交易所运营方
- 触发时机：撮合引擎完成订单匹配的瞬间，同步触发上链
- 上链要求：与下单阶段的原始订单哈希锚定，不可拆分篡改；核心目的：留存撮合全流程记录，防止恶意插针、虚假匹配、对敲交易，为成交结果提供可信依据

### 3. 成交确认与清算阶段（成交即确权，清算结果双向锚定）
- 具体数据项：成交单唯一ID哈希、对应买卖双方订单ID哈希、成交价格、成交数量、成交金额、手续费明细哈希、持仓变动哈希、资金变动哈希、清算可信时间戳、交易所清算系统签名、资金存管机构清算回执哈希
- 上链主体：交易所运营方 + 资金存管机构
- 触发时机：成交确认完成、资金清算执行的同时，触发上链
- 上链要求：与订单、撮合记录哈希双向锚定，资金存管机构的清算回执必须与成交记录一一对应；核心目的：实现成交与资金变动的强绑定，确保交易真实可验，杜绝虚假成交、资金挪用

### 4. 订单状态全变更阶段（变更即留痕，全流程可追溯）
- 具体数据项：订单ID哈希、变更后状态（部分成交、全部成交、用户撤单、系统撤单、过期失效、异常驳回）、变更触发主体、变更可信时间戳、变更主体数字签名
- 上链主体：触发变更的对应主体（用户/交易所/风控机构）
- 触发时机：订单状态发生变更的瞬间，实时触发上链
- 上链要求：必须与原始订单哈希锚定，状态变更不可逆；核心目的：全流程记录订单生命周期，防止无理由撤单、恶意冻结订单，责任可追溯

## （二）配套合规监管核心上链数据
1.  **主体身份与合规资质类数据**：所有参与主体的工商登记信息哈希、金融持牌资质哈希、准入审批记录、授权文件哈希、身份核验结果、数字证书公钥、权限变更记录；变更实时上链，国密签名确权，防止主体冒用、资质造假、越权操作
2.  **用户资产与资金存管核心数据**：用户充值/提现申请哈希、资金存管机构流水回执哈希、日终用户全量账户资产余额哈希、交易所资金池总余额哈希、存管银行对账结果哈希；与对应成交记录锚定，实现账实一致核验，杜绝资金挪用
3.  **风控合规与异常处置数据**：风控规则哈希、异常交易识别记录、风险等级调整、限制交易操作、强平记录、异常告警记录、用户申诉记录、整改闭环记录；与对应订单/成交记录锚定，全流程留痕，防止暗箱处置
4.  **审计与监管执法数据**：监管检查记录、问询函件、整改要求、处罚文书、执法指令、第三方审计报告哈希、整改闭环记录；实时上链，多主体签名确权，执法全流程可追溯、合规可举证

# 四、FISCO BCOS链上架构与撮合引擎深度融合实现要求
## 1. 节点拓扑与部署架构（适配高性能撮合需求）
- 采用「**核心记账节点集群（交易所）+ 授权记账节点集群（存管/审计/风控）+ 专属监管节点 + 轻量用户查询节点**」的联盟链架构，所有节点必须通过准入审批方可接入，严禁无授权节点接入
- 交易所撮合引擎集群与链上核心记账节点集群采用**低延迟内网同城双活部署**，确保订单下达、撮合、上链的毫秒级并行联动，无网络阻塞
- 核心节点采用**跨机房/跨城市容灾部署**，主备集群实时同步状态，单节点/单机房故障不影响链上服务与撮合业务连续性
- 采用**读写分离架构**：订单上链、存证、确权等写操作仅路由至核心记账节点；用户订单核验、监管审计查询等读操作全部路由至专属只读节点，避免读请求阻塞核心上链业务

## 2. 多群组业务隔离架构（FISCO BCOS原生核心优势，保障高并发）
- 基于FISCO BCOS多群组特性，按业务线进行链上资源隔离，每个群组独立共识、独立存储、互不影响，避免业务拥堵，支持横向扩展：
  - 群组1：现货订单全生命周期存证与确权
  - 群组2：合约订单全生命周期存证与确权
  - 群组3：资金存管与清算对账
  - 群组4：风控合规与监管审计
- 新增业务线无需改造主链，仅需新建对应业务群组，实现无缝扩展，完全不影响现有交易业务

## 3. 核心智能合约体系（模块化设计，与撮合业务深度适配）
必须采用模块化松耦合设计，严禁单合约全量耦合，所有合约必须明确调用权限、触发条件、验签规则，核心合约模块如下：
1.  **身份与权限管理合约**：负责主体身份上链、节点准入审批、权限分级控制、国密签名验签，是所有链上操作的身份基础
2.  **订单存证与核验核心合约**：本系统的核心合约，负责订单全生命周期数据的上链存证、哈希锚定、状态更新、用户自主核验接口、订单真实性校验逻辑，与撮合引擎通过专属API联动
3.  **资金清算与对账合约**：负责资金流水、资产余额、清算回执的上链存证，自动实现链上成交记录与存管机构资金流水的哈希比对，账实不符自动触发告警
4.  **监管审计专属合约**：负责监管节点数据实时同步、全链路穿透查询、批量订单/交易一键核验、异常规则订阅与告警推送、监管指令上链与执行跟踪
5.  **风控与处置合约**：负责风控规则哈希上链、异常交易告警上链、风险处置流程留痕、处置结果与对应订单锚定
- 性能优化要求：高频调用的哈希校验、签名验签、批量订单存证逻辑，必须采用FISCO BCOS预编译合约（C++底层实现）开发，性能远超Solidity合约，满足高频交易上链需求

## 4. 订单上链与撮合引擎联动的时序设计（核心性能保障，零阻塞撮合）
必须采用「**双轨异步并行+强哈希锚定**」的时序设计，既保障链下撮合的高性能，又实现订单全流程上链的不可篡改，绝对禁止链上操作阻塞撮合引擎：
1.  下单阶段：用户发起下单指令，用本人私钥对订单进行SM2签名，生成唯一订单哈希；系统并行执行两个操作：① 将带签名的订单哈希实时发送至FISCO BCOS链上，通过订单存证合约完成上链存证；② 将订单同步发送至中心化撮合引擎，进入撮合队列，两个操作互不阻塞
2.  撮合阶段：撮合引擎完成订单匹配，生成撮合记录与成交单；系统并行执行两个操作：① 将撮合记录哈希、成交单哈希实时上链，与原始订单哈希完成锚定确权；② 同步执行成交清算与持仓更新，两个操作互不阻塞
3.  清算阶段：资金存管机构完成资金清算，生成清算回执；系统将清算回执哈希上链，与对应成交单哈希完成双向锚定，自动触发对账校验
4.  日终闭环：系统自动完成当日全量订单、撮合记录、成交单、清算数据的链上链下全量哈希校验，生成对账报告上链，异常数据自动触发监管告警

## 5. 高性能与高可用保障要求
- 共识优化：采用FISCO BCOS优化版PBFT共识，支持视图切换优化、共识节点热加入/热退出，单节点故障恢复时间控制在秒级，不影响业务连续性
- 并行执行：基于FISCO BCOS的DAG并行计算能力，无依赖关系的订单存证交易可并行执行，大幅提升链上TPS，满足高频批量订单上链需求
- 冷热数据分离：链上仅保留近12个月的热数据，超过时限的历史归档数据存储至链下合规对象存储，链上仅留存数据哈希摘要，确保链上存储轻量化，查询性能稳定
- 弹性扩展：基于K8s实现节点资源弹性调度，交易高峰期自动扩容核心记账节点资源，低谷期自动缩容，保障资源利用率与业务稳定性

# 六、安全与合规强制要求
1.  数据隐私保护：用户完整身份证号、银行卡号、交易密码、未公开的持仓信息等敏感数据严禁明文上链，仅可脱敏后上链SM3哈希摘要，原文仅存储在交易所合规加密数据库，仅监管机构有权依法调取
2.  私钥与签名安全：所有节点私钥、用户签名私钥必须采用硬件加密机/HSM保护，严禁明文存储；所有上链数据必须经过对应主体的国密签名验签，确保数据来源可信
3.  合规适配：完全符合国内金融监管部门对交易场所的持牌经营要求，支持反洗钱（AML）、客户身份识别（KYC）数据的链上合规存证，支持监管数据一键导出、与监管系统跨链对接
4.  应急与容灾：设计完整的节点故障切换、链上数据应急恢复、业务连续性保障方案，定期开展容灾演练与性能压测
5.  智能合约安全：所有合约必须经过第三方权威机构安全审计，支持灰度发布、热升级，严禁出现合约漏洞、越权调用风险
