# 资金闭环设计
## 链上钱包设计
一个做市商对应有一个或多个链上钱包合约，合约只认做市商的外部地址，权限独立。
联盟链做市商的标准方案，链上钱包地址所属权不公开，只有平台知道哪个地址属于谁，做市商只能看到自己的，区块链上虽然能查到余额，但不知道是谁的。链上钱包合约不存储、不暴露 做市商身份，前端只返回当前登录做市商自己的数据。
效果：链上是公开的，但谁也不知道哪个钱包是谁，资产安全、策略保密，平台可监管、可风控。

银行/景区分别有一个外部地址，和一个或多个链上钱包地址，银行专设有一个**专属自动销毁合约账户，链上钱包**，景区/做市商做赎回时，将法币通证转到该合约，合约收到后，不能转出，多签认证后，合约自动执行链上销毁。

银行作为发行方，是法币通证的唯一发行/兑付主题，合规性、风险可控性、审计可追溯是第一优先级，我们设计以下方案来保证这几个核心诉求：
- **发行-销毁全链路闭环**：链上可查，不可篡改，规则透明，符合监管审计要求，法币凭证只能在交易所链上账户交易划转；
- **智能合约自动执行**：操作风险为零，杜绝人工操作失误、私钥泄漏导致的资金挪用/丢失风险；
- **流通量全链可以验证**：联盟内的所有节点都能实时验证通证的发行总量、流通量、销毁量，无暗箱操作
- **账户风险隔离**: 发行账户、销毁账户、运营账户独立，单一账户出现风险不会波及全体系。

## 银行销毁通证流程
1. 银行法币通证回收销毁专属合约：
    - 仅支持指定的法币通证，无任何转出功能
    - 收到通证后，自动、实时执行链上销毁，直接扣减通证总流通量
    - 合约开源、无后门、无任何私钥控制，全联盟节点可验证代码逻辑。
2. 景区/做市商发起赎回，用自己的外部账户签名，将需要赎回的法币通证，直接转入该销毁合约地址；
3. 链上销毁完成后，自动触发事件通知，银行核验链上销毁记录无误后，给赎回方兑付等额法币，完成全链路闭环。（升级方案：数字人民币准备金机制，每发行一元法币通证，托管合约存入1元数字人民币准备金，销毁完成，合约直接将数字人民

## 全链路闭环业务流程
流程 1：法币通证发行（·银行→做市商）
- 做市商完成银行 KYC/AML，向银行对公账户转账法币
- 银行核验资金到账后，用发行 外部 主账户多签，在链上 mint 等额法币通证，直接转入做市商的实名 外部 主账户
- 链上发行记录全节点可查，通证总发行量实时更新，公开透明

流程 2：门票发行与交易（景区→用户 / 做市商）
- 景区用发行 外部 主账户签名，发行门票通证，转入景区的运营链上钱包，在平台上架销售
- 用户 / 做市商购买门票，支付的法币通证自动进入景区的运营链上钱包；
- 景区可随时用 外部 主账户签名，将运营链上钱包里的回款，转回自己的发行 外部 主账户。

流程 3：做市商交易做市
- 做市商根据交易需求，用 外部 主账户签名，将法币通证从主账户转入交易链上钱包；
交易链上钱包里的资金，仅可用于平台内的挂单做市、撮合交易，无法转出到其他陌生地址；
做市商可随时将闲置 / 盈利资金，从交易链上钱包转回自己的 外部 主账户。
流程 4：法币通证赎回销毁（核心闭环）
景区 / 做市商发起赎回，用自己的 外部 主账户签名，将需要赎回的法币通证，直接转入银行的销毁合约账户；
销毁合约收到通证后，自动执行全额销毁，链上实时扣减通证总流通量，全程无人工干预；
链上销毁完成后，自动触发链下事件通知，银行核验链上销毁记录无误后，向赎回方的对公账户兑付等额法币，完成闭环。
